EXAMPLE 1 · PYTHON

Make a numeric prediction and inspect every contribution

A weighted sum is the same arithmetic as a shopping bill. Each feature contributes its value times its weight.

Complete code

features = [2, 3]
weights = [4, -1]
contributions = [x * w for x, w in zip(features, weights)]
bias = 1
prediction = sum(contributions) + bias
print(contributions)
print(prediction)

Expected output

[8, -3]
6

Read it step by step

  1. Each feature pairs with its corresponding weight; the assumed list lengths match.
  2. The contributions are 2×4=8 and 3×(−1)=−3.
  3. Their sum is 5, then the fixed bias adds 1.
  4. zip stops at the shorter input, so production code should validate equal lengths rather than silently accept mismatches.

Remember: A negative weight reduces a score; its meaning depends on the feature and fitted model.

EXAMPLE 2 · PYTHON

Measure prediction error with MSE

Mean squared error turns a list of residuals into one nonnegative summary.

Complete code

actual = [2, 4, 6]
predicted = [1, 5, 6]
errors = [p - y for p, y in zip(predicted, actual)]
squares = [e * e for e in errors]
print(errors)
print(squares)
print(f"MSE={sum(squares) / len(squares):.4f}")

Expected output

[-1, 1, 0]
[1, 1, 0]
MSE=0.6667

Read it step by step

  1. Subtract actual from predicted consistently to define each residual.
  2. Squaring prevents negative and positive residuals from canceling.
  3. Sum the squares and divide by the number of examples.
  4. :.4f displays four decimal places; the internal division is not rounded at that earlier step.

Remember: MSE emphasizes larger errors and uses squared target units. It is not the only sensible loss.

EXAMPLE 3 · PYTHON

Follow gradient descent for three steps

This is a one-parameter training example with a known minimum at w=3.

Complete code

w = 0.0
rate = 0.1
for step in range(1, 4):
    gradient = 2 * (w - 3)
    w -= rate * gradient
    loss = (w - 3) ** 2
    print(f"step={step} w={w:.4f} loss={loss:.4f}")

Expected output

step=1 w=0.6000 loss=5.7600
step=2 w=1.0800 loss=3.6864
step=3 w=1.4640 loss=2.3593

Read it step by step

  1. The derivative of (w−3)² is 2(w−3), evaluated at the current w.
  2. Subtract rate times gradient to move locally downhill.
  3. Recalculate loss after the update so the printed weight and loss match.
  4. The loss decreases here; a rate that is too large can make this same procedure diverge.

Remember: An optimization example is not evidence that every model will find a global minimum.

EXAMPLE 4 · PYTHON

Calculate softmax without enormous exponentials

Softmax turns scores into positive values summing to one. Subtracting a shared maximum leaves the probabilities unchanged.

Complete code

from math import exp
scores = [1000.0, 1001.0]
largest = max(scores)
scaled = [exp(x - largest) for x in scores]
total = sum(scaled)
probabilities = [x / total for x in scaled]
print([round(p, 4) for p in probabilities])
print(f"sum={sum(probabilities):.4f}")

Expected output

[0.2689, 0.7311]
sum=1.0000

Read it step by step

  1. Direct exp(1000) can overflow; shifting gives exponent arguments −1 and 0.
  2. Exponentials are positive, then division by their sum normalizes them.
  3. The larger score receives the larger probability.
  4. The example rounds only the displayed list. Very tiny probabilities can still underflow in extreme cases; log-softmax is useful when log probabilities are needed.

Remember: A numerically stable formula can be algebraically equivalent to an unstable one.

EXAMPLE 5 · PYTHON

Compute a Bayes update with counts

Fictional item flags illustrate why a useful detector can still produce many false alarms.

Complete code

faulty_and_flagged = 8
good_and_flagged = 18
flagged = faulty_and_flagged + good_and_flagged
posterior = faulty_and_flagged / flagged
print(f"Flagged: {flagged}")
print(f"Faulty among flagged: {posterior:.2%}")

Expected output

Flagged: 26
Faulty among flagged: 30.77%

Read it step by step

  1. Restrict attention to the group already known to be flagged.
  2. Count all flags, including false alarms, to obtain the correct denominator.
  3. Divide the faulty flags by all flags.
  4. :.2% converts a fraction into a displayed percentage with two decimal places.

Remember: This is the probability of a fault given a flag, not the probability of a flag given a fault.

EXAMPLE 6 · PYTHON

Build an attention-weighted mixture

Attention mixes value vectors using weights. This example supplies the weights so the mixing step is easy to inspect.

Complete code

weights = [0.25, 0.75]
values = [[2, 0], [0, 4]]
result = [
    sum(weight * value[j] for weight, value in zip(weights, values))
    for j in range(2)
]
print(result)

Expected output

[0.5, 3.0]

Read it step by step

  1. Each value vector has two coordinates.
  2. For the first coordinate, calculate 0.25×2+0.75×0=0.5.
  3. For the second, calculate 0.25×0+0.75×4=3.
  4. A complete attention layer calculates weights from queries and keys; this snippet isolates the weighted-value calculation.

Remember: The vector output keeps its coordinate dimension while combining information across positions.

EXAMPLE 7 · PYTHON

Standardize using training information only

Preprocessing is part of the fitted procedure. Use the training mean and scale for later examples.

Complete code

from statistics import mean, pstdev
train = [2, 4, 6]
center = mean(train)
scale = pstdev(train)
new_value = 8
z = (new_value - center) / scale
print(f"mean={center:.1f} scale={scale:.4f}")
print(f"new z={z:.4f}")

Expected output

mean=4.0 scale=1.6330
new z=2.4495

Read it step by step

  1. mean computes the training center. pstdev uses the population denominator over the training values for this scaling convention.
  2. The new value does not enter the fitted mean or scale.
  3. Subtract the stored center and divide by the stored positive scale.
  4. A constant training feature has zero scale and needs an explicit handling rule before division.

Remember: Including held-out data in fitted preprocessing can leak information into evaluation.

EXAMPLE 8 · PYTHON

Check a tiny classifier beyond accuracy

Counts of true and false positives answer different questions from overall accuracy.

Complete code

tp, fp, fn, tn = 30, 10, 20, 40
precision = tp / (tp + fp)
recall = tp / (tp + fn)
accuracy = (tp + tn) / (tp + fp + fn + tn)
print(f"precision={precision:.2f}")
print(f"recall={recall:.2f}")
print(f"accuracy={accuracy:.2f}")

Expected output

precision=0.75
recall=0.60
accuracy=0.70

Read it step by step

  1. Precision asks how many predicted positives were actually positive.
  2. Recall asks how many actual positives were found.
  3. Accuracy counts all correct labels over all labels.
  4. The example denominators are nonzero; a reusable implementation needs a documented convention for undefined precision or recall.

Remember: Choose metrics that match the consequences of mistakes, not only the largest-looking score.
