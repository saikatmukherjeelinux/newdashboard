EXAMPLE 1 · BASH

Print predictable lines with printf

Use a fixed set of fictional names as input. These examples target Bash with GNU/Linux utilities; they do not execute in the web page.

Complete code

printf '%s\n' 'Ada' 'Ben' 'Cara'

Expected output

Ada
Ben
Cara

Read it step by step

  1. printf is a shell command that formats arguments.
  2. %s means print the next argument as text. The format’s \n means end the line.
  3. The format is reused for each remaining argument, producing one line per name.
  4. Single quotes preserve text literally. This command has a format argument, not a dash-prefixed option.

Remember: Prefer printf for predictable formatting; echo handling of escapes varies across environments.

EXAMPLE 2 · BASH

Find matching lines and show their positions

A pipe sends one command’s output to the next command’s input. grep selects lines matching a pattern.

Complete code

printf '%s\n' 'INFO ready' 'ERROR disk' 'ERROR network' | grep -n 'ERROR'

Expected output

2:ERROR disk
3:ERROR network

Read it step by step

  1. printf supplies three lines to the pipe.
  2. grep reads those lines from standard input.
  3. -n prefixes each match with its original line number, starting at 1.
  4. The pattern ERROR matches these uppercase strings; this example does not use -i for case-insensitive matching.

Remember: Line numbers refer to the input stream. grep normally returns status 1 when no line matches; that is not the same as a tool error.

EXAMPLE 3 · BASH

Count repeated labels after sorting

uniq combines adjacent identical lines. Sorting first makes all identical labels adjacent.

Complete code

export LC_ALL=C
printf '%s\n' 'red' 'blue' 'red' 'blue' 'red' | sort | uniq -c | awk '{print $1, $2}'

Expected output

2 blue
3 red

Read it step by step

  1. LC_ALL=C requests a consistent byte-oriented sorting locale for this example.
  2. sort orders the lines; it does not count them.
  3. uniq -c adds an occurrence count. The -c option means count.
  4. awk prints its first and second whitespace-separated fields with one space, removing uniq’s padding from the displayed output.

Remember: uniq alone only notices adjacent duplicates, so input ordering matters.

EXAMPLE 4 · BASH

Sort numbers as numbers

Text sorting and numerical sorting answer different questions. Specify the intended interpretation.

Complete code

printf '%s\n' 10 2 30 | sort -n

Expected output

2
10
30

Read it step by step

  1. The input lines contain decimal integer text.
  2. sort -n compares numerical values instead of ordinary text order.
  3. Without numerical comparison, text beginning with 1 may come before text beginning with 2.
  4. Add -r together with -n if you deliberately want largest first; this example keeps ascending order.

Remember: GNU sort -n and -g have different numeric parsing rules. Use -g when you specifically need its general numeric format behavior.

EXAMPLE 5 · BASH

Filter rows with awk and calculate a total

The fictional input has two whitespace-separated fields: a product name and a quantity.

Complete code

printf '%s\n' 'pen 3' 'book 5' 'bag 2' | awk '$2 >= 3 {total += $2; print $1} END {print "total", total}'

Expected output

pen
book
total 8

Read it step by step

  1. $2 names the second field. The condition $2 >= 3 selects the first two rows.
  2. Inside braces, total += $2 accumulates selected quantities and print $1 displays the product.
  3. END runs once after all input lines and prints the accumulated total.
  4. The single-quoted program is an awk argument, not a shell variable expression. There are no command flags in this example.

Remember: The field format is part of the example. This is not a general CSV parser with quoted commas or embedded newlines.

EXAMPLE 6 · BASH

Replace text using sed

sed can transform a stream without changing any existing file. This example replaces a word on every line.

Complete code

printf '%s\n' 'red red' 'blue red' | sed 's/red/green/g'

Expected output

green green
blue green

Read it step by step

  1. s introduces substitution; the slashes separate pattern, replacement and modifiers.
  2. red is the pattern and green is the replacement.
  3. The final g replaces every match on each line. Without it, only the first match on each line is replaced.
  4. No -i option is used: the transformed text goes to standard output, not back into a file.

Remember: sed patterns are regular expressions. Special characters need appropriate escaping when you intend literal matching.

EXAMPLE 7 · BASH

Select a delimited field with cut

cut extracts positions or fields from simple delimited text.

Complete code

printf '%s\n' 'Ada:10' 'Ben:20' | cut -d ':' -f 2

Expected output

10
20

Read it step by step

  1. -d chooses the delimiter, here a colon.
  2. -f 2 selects the second field on each input line.
  3. Single quotes make the colon an explicit literal argument.
  4. The names are omitted and the quantity field is printed on its own line.

Remember: For real CSV with quoting rules, use a CSV-aware parser rather than assuming cut handles every case.

EXAMPLE 8 · BASH

Count a filtered result and inspect exit status

Commands communicate through both printed output and an exit status. They are different channels of information.

Complete code

printf '%s\n' 'INFO ready' 'ERROR disk' 'ERROR network' | grep -c 'ERROR'
printf '%s\n' 'INFO ready' | grep -q 'ERROR'
status=$?
printf 'status=%s\n' "$status"

Expected output

2
status=1

Read it step by step

  1. grep -c prints the number of matching lines, here 2; it counts lines, not occurrences within each line.
  2. grep -q runs quietly and prints no matches.
  3. $? immediately after that pipeline is the status of its last command under this ordinary Bash pipeline configuration. Save it before another command changes it.
  4. Status 1 means no match for grep. The quoted "$status" passes one argument to printf.

Remember: These commands are for an ordinary interactive Bash session without set -e; automatic exit-on-failure scripts need deliberate handling of no-match results.
